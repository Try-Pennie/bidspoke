Partners page design

The settled design for issue #2114, chosen by Dan over 61 design rounds on 2026-10-13 and 2026-10-14, one decision per round. The first frame works; the rest each show one moment of the same page. Below them: every decision with its reason, the behaviour changes the design commits to, and which parts are artefacts of drawing it as a static page.

    Decisions, in the order they were made

    1. Layout tabs, one group at a time.
    2. Partner list grouped into Buyers and Sources, alphabetical, name only. List order is gone.
    3. Tabs only the ones that apply. Bid Group shows when a workflow names the partner or a Bid Group setting is filled in.
    4. Density compact, settings start 138px in, section names on the first line of their settings.
    5. Colour navy for selections, blue only for buttons. A standing rule for the whole app.
    6. Header name and slug.
    7. States chip grid.
    8. Sold on Enabled on its own row, then Sold on with Offer and Click.
    9. Hours shared hours first, with a link to set each day separately.
    10. Time zone a setting under Hours that changes only how times are shown. Hours still run Eastern, the click count still resets at midnight Pacific.
    11. Caps field and bar.
    12. Click delivery flat routes, no boxes.
    13. Sale click URL and routing code side by side, the placeholder tinted and scrolling with the address.
    14. Held clicks cards that say what each button does.
    15. Outcome rules shown only for buyers sold on the offer, drawn as rows with headings said once.
    16. Blackout dates a list, one row per day off with its weekday.
    17. Entering a date and a time a date is typed, like Jan 1, 2027, with a button inside the box that opens a small month calendar; a time is typed, like 9:00 AM, with no picker. Settled in round 1 of #2137 (2026-10-15), option "Typed, with a calendar".
    18. Controls one dropdown used everywhere in the app, never a second copy. It, the switch, the calendar's popover, the dialog and the tabs are built on Radix and styled to this design.
    19. Pricing one table of Engine tiers, one line for the lead types not priced yet.
    20. Bid resolution Resolver, Endpoint and Bid amount as separate rows, tiers drawn like the Pricing table.
    21. Bid mode removed. Nothing in Bidspoke acts on it.
    22. Request and Response two rows, each with one line of plain meaning.
    23. Duplicate check inside the Endpoint row, explained in one line.
    24. Workflow values a new tab for what workflows read by name: click URL, sell-off copy, sub-account IDs and minimum bids.
    25. Limits Daily attempt cap and Minimum bid fields, one line saying what each does.
    26. Circuit breaker Errors, Within and Pause for fields in minutes, one line saying what it does.
    27. Confirmation window hidden until a Latency Gate names the partner or it is set up. No workflow has one.
    28. Errors Retry and Never retry lists, starting with the defaults as fixed rows marked Default. Your own rules are checked first.
    29. Alerts an Alert switch on each Errors list, no separate Alerts row.
    30. Workflow values tab each value, the exact name workflows read it by, and what reads it. The Sale row keeps only the routing code.
    31. Partner tab Name, Does (Sends us leads, Buys leads), Active with what off means, and Sold through with the Bid Group set up button.
    32. History grouped by day, time and who beside each save, editors by name, no repeated History heading.
    33. History wording each change in plain words, old value struck through, an arrow, the new value in bold.
    34. Source partners Partner, Workflow values and History tabs. The sell-off offer is edited beside a preview of how it is shown.
    35. Partner list as drawn: a large Partners heading, + New, Buyers and Sources headings, the selected partner on a beige fill.
    36. Delete and Discard Delete goes last on the Partner tab. Discard changes sits beside Save and shows only when there is something to discard.
    37. Delete in a pale red box at the foot of the Partner tab, and it takes DELETE typed exactly.
    38. DELETE confirmation typed inside the red box, which says what is removed; the button turns on only when DELETE is typed exactly. A partner sales still refer to says it cannot be deleted instead.
    39. Save bar appears only when something is edited, as a dark bar naming what changed, with Discard changes and Save changes.
    40. After Save the dark bar changes in place: Saving with the seconds counting, then Saved with Undo, then it slides away. A failure stays, says why and offers Try again.
    41. Leaving unsaved our own dialog naming the change: Keep editing, Discard and open the other partner, Save and open it.
    42. New partner its own page asking for name, slug and what it does, with Cancel and Create partner in the dark bar.
    43. Nothing selected the right side keeps a short prompt to pick a partner or create one.
    44. Loading grey placeholders with a moving shimmer while the request is live; after 30 seconds it becomes an error.
    45. Load failure the right side says the partners could not be loaded, why, that nothing has changed, and offers Try again.
    46. No buyer profile the Buyer profile tab stays, saying the buyer is not offered leads through buyer selection, with Set up a buyer profile.
    47. Missing credential red, under the Secret field it is about, with a red dot in the list and on the tab; opening the partner lands on the tab with the problem.
    48. Cannot be deleted the red Delete box stays, with no field or button, saying sales refer to the partner and that turning off Active stops it.
    49. Bid Group tab opens with a row saying which workflows use it, worded in this round.
    50. Bids in the Bid Group tab's first row names the workflows and says both buyers are asked and the higher bid wins.
    51. Tabs plain words, the open tab bold with a navy line under it.
    52. Controls outlined white boxes with a thin beige line and rounded corners.
    53. Priority the rule in one line, then where the buyer stands today (Tripoint is the only buyer sold on the offer).
    54. Offer buyer caps a table, Leads and Spend by Per hour and Per day, empty reading No cap.
    55. Unresolved sales cards like held clicks, each button followed by what it does.
    56. Sample answer a box under Extract holding a pasted answer, used to offer paths while setting up; not used when bidding.
    57. Bid Group order Bids in, Endpoint, Resolver, then Bid amount; Resolver and Bid amount stay two separate choices.
    58. Formula names the resolver option reads No call; Bid amount keeps Formula.
    59. Refused save the bar names the field and its tab with Show me; the tab gets a red dot and the field is marked red with the reason.
    60. Someone saved first a dialog. Saving keeps your changes and adds theirs; only fields you both changed need a choice. (A behaviour change: today Take theirs discards all your edits.)
    61. Merging saves fields you have not touched update by themselves when someone else saves; the grouped dialog appears only when you both edited the same field.
    62. Click delivery changes no second confirmation. The bar says what the change does (Clicks from WY will go to DI4 instead of DV1) beside the one Save button.
    63. Mark sent pressing it opens an optional lead id box in the card; without an id the click is still counted and Completed in Salesforce.
    64. Salesforce not fully updated every record listed with its result, the failure in Salesforce's own words, then Retry Salesforce and Remove from the list (which asks first).
    65. Grey hint text #697081, the lightest grey of the same hue that clears WCAG AA on both surfaces it sits on (4.60 to 1 on the beige page, 4.51 behind code on gray-100, 4.96 on white), so hints stay as quiet as they are and step back from the labels as far as AA allows. Today's text-gray-500 fails (4.48 on beige); the darker 6 to 1 option sat too close to the labels. One token, text-hint, app wide through the shared Field. Settled in round 1 of #2144 (Dan, 2026-10-16), option "Just passes". Section names stay dark, as drawn.
    66. Collections cap in Eligibility, as two rows of two: Debt minimum and Debt maximum, then Loan amount minimum and Collections at most, so every field is the same width. Labelled Collections at most, with the box taking only the number and "% of debt" written beside it, and one line under it: a lead whose collections are more than this share of its debt is skipped; empty means no limit ("skipped" rather than "not offered", which the page already says of a buyer offered nothing). Settled in rounds 1 and 2 of #2268 (2026-10-17).
    67. A box holds only what is typed any fixed words of a value (a unit such as "% of debt") sit beside the box, never inside it as if typed. Dan, 2026-10-17, asked whether he would have to type "of debt" when it was drawn inside the box. A standing rule for the whole app.

    Behaviour changes the design commits to

    1. Live merge of another person's save While you edit, a save by someone else updates every field you have not touched, live. Today a save made by someone else first is a conflict for the whole form.
    2. Field level merge Only a field you both changed asks a question, grouped by section, with Keep yours or Use theirs for each. Saving keeps your choices and adds the rest of theirs. Today "Take theirs" discards every edit you made.
    3. Mark sent without a lead id The partner's lead id becomes optional when marking a held click sent. Without it the click is still counted and Salesforce still marks the sale Completed, with no partner lead id. Today the route refuses an empty id.
    4. Bid mode removed The Commit and Ping only setting is removed from the page: nothing acts on it (the Partner Bid step copies it into its resolved input and the money gate records it in its snapshot; neither changes what is sent).
    5. Display time zone, stored per buyer A buyer profile gains a time zone, Eastern, Central, Mountain or Pacific, used only to show hours and reset times. Hours stay stored and judged in Eastern; the click count resets at midnight Pacific, shown as the hour that is in the chosen zone on the night it happens (3:00 AM Eastern on most nights, 4:00 AM on the March clock change night and 2:00 AM on the November one).
    6. Default error rules shown as fixed rows The built in retry and never retry answers are listed as rows marked Default that cannot be edited; your own rules are checked first, and each list carries its own Alert switch.
    7. A partner opens where its problem is A partner with an issue (a missing credential, a refused field) opens on the tab holding it, with red dots on the list row and the tab.
    8. Delete knows about sales up front The page reads whether sales refer to the partner before offering Delete, and explains the block instead of offering a field that would fail.
    9. Editors shown by name History names each editor, resolved from the users table, rather than an email address.
    10. Workflow values tab The values workflows read by name move to their own tab, each showing the exact name and the workflows that read it. The click URL moves here from the Sale row.
    11. Only tabs that apply Bid Group shows when a workflow's Bid Group names the partner or any Bid Group setting is set. The Confirmation window shows only when a Latency Gate names the partner or it is set up.
    12. Colour rule for the whole app Navy #1D212F marks a selection; blue #1B72BA is for buttons only. Red is reserved for a genuine problem.

    Drawn this way only because this is a static page

    1. The builder is not the component tree The frames are drawn by a small function that makes DOM nodes. The real page is React in apps/web; build it from the app's own components and Tailwind classes, not by porting this script.
    2. Controls are drawn, not real Inputs, switches and buttons here are styled boxes with no behaviour. Every one becomes the design system control for its kind, with keyboard and screen reader support.
    3. The fixed window Each frame is a 1020 by 760 window with its own scroll, so the states can sit side by side. The real page fills the browser.
    4. Fonts are embedded Mori is embedded so this file renders with no network. The app loads its fonts its own way.
    5. Sample data Held clicks, blackout dates, the conflicting save by Brian Nelms, the refused click URL and the Salesforce failure are invented to show a state. Partner names, settings, sales counts and workflow names are real as of 2026-10-14.
